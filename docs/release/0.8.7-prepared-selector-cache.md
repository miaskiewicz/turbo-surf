# Prepared selector reuse, v0.8.7

Detached React construction changed the native storage version and repeatedly
prepared otherwise identical stylesheet selector targets. A native six-read
control already reused one solved layout and one raw stylesheet export, but
prepared its selector targets six times.

The prepared-sheet key now compares fresh opaque connected-document checkpoints
when available. Missing checkpoints retain a distinct full-storage-version key.
Document, root, owning context, CSSOM/live-state revisions, and the complete
composition remain part of admission. Building and storing a new entry still
requires the original full native version and current checkpoint to match.
Every geometry operation continues to capture fresh native input; no stale
capture is submitted to a new layout.

All four DOM-family development patches and lockfile sources resolve to
`eb040c84c150b30e30c2483a39b8784e44a4da93`, which adds connected-shadow support to
the checkpoint contract. The canonical owner-context/document lookup is shared
between the prepared-sheet and solved-layout keys.

Validation:

- Native regression: selector preparation **6 → 1**, with unchanged widths,
  one layout, and five solved-layout hits.
- **19/19** focused native controls pass: cache reuse/invalidation, open and closed
  connected shadow roots, checked-state and CSSOM changes, retained-scroll
  animation admission, and scroll/hit ownership.
- Strict workspace/all-target Clippy, formatting, and Rust complexity ≤15 pass.

These are incremental integration results. The original payroll mapping case,
the general presented-animation integration, latest-package auth 46/46, and the
wider payroll suite require subsequent acceptance. Independent pre-existing
validity/focus-selector controls are retained separately; this change does not
claim to repair their behavior.
